# Owner's critiques and taste

The owner's own judgement, in his words where possible. The critic reads this file before the rubric,
and it outranks the rubric. Copy it into the real portfolio repo's `design/` folder.

## 2026-10-29: blind test B4 (portfolio)

- **Chose A over B.** "I really really like A." A is the richer, conventional developer portfolio:
  - a sticky nav and a meta strip with the local time
  - a large name
  - a serif italic statement
  - a three-part focus strip and a project index
  - mono labels and a warm orange accent

  B was the sparse, novel version: a cinnamon field and an inverted hierarchy. Richness and a
  familiar structure won.
- **Theme.** "I prefer dark theme."

## 2026-10-29: on dark A

- **Name size.** "My name appears too big on desktop." The display size was 168px at 1440 wide
  (11.5vw). Keep the name prominent, but it should not dominate the first screen on desktop.
- **Footers matter.** "I like really beautiful footers … like Apple, even when many people don't
  see the hardware inside they make it beautiful." The footer should get the same care as the hero:
  structured, precise, small type, nothing left at default.
- **Project cards.** He hates "AI slop cards showing projects; that's something every portfolio
  does". Present work in a way that is not a card grid.
- **Icons.** He wants "really tasteful icons, no AI slop icons". Only where they help, never as
  decoration.
- **Mono labels, serif italics, warm accent.** These are allowed. The catalogue calls them tells; he
  chose them.
